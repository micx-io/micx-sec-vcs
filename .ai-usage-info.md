# MICX Sec VCS SDK — AI Usage

Dieses SDK trennt Git-Zugriffe von der Anwendung: Der isolierte VCS-Worker
verwahrt den passwortlosen Git-SSH-Key als Secret. Die Anwendung spricht mit
ihm ausschließlich über RabbitMQ und nutzt die ausgecheckten Dateien über
ein gemeinsames Volume. So bleibt der SSH-Key aus den App-Containern heraus.

Für lokale Entwicklung braucht es keinen Git-Worker: Eigene Mock-Verzeichnisse
können direkt im Projekt liegen und unter denselben Repository-URLs registriert
werden. Die Anwendung nutzt in beiden Betriebsarten das gleiche Interface.
Ohne aktivierten Mock-Modus sind ausschließlich Remote-Git-URLs zugelassen.

## Verwendung

```php
const DEVELOPMENT_MODE = true; // In Produktion false setzen.

$manager = new MixSecVcsClient(
    sharedDirectory: '/vcs-share',
    connector: 'rabbitmq://user:password@rabbitmq:5672/micx.vcs.v1',
    storageTemplate: '{repo}/{branch}',
);
$manager->addMockDir(
    'git@github.com:example/repo1.git',
    'main',
    __DIR__ . '/mock-repos/repo1'
);

// Mappings dürfen in Produktion im Code bleiben; nur Dev-Modus nutzt sie.
$manager->setAllowMockDir(DEVELOPMENT_MODE);

$repo = $manager->getRepository(
    'git@github.com:example/repo1.git', branch: 'main', directory: 'sites/repo1'
);
$repo->setCommitUser('Jane Doe', 'jane@example.com');
$repo->commit('Update content');
$repo->sync(); // Abgleich mit Remote-Repository (Pull + Push).
$directory = $repo->getDirectory();
```

Das Shared Directory (z. B. `/vcs-share`) muss als vorhandener Mount direkt
unter dem Dateisystem-Root eingebunden sein. Im Worker liegt dasselbe
Volume unter `/data`. Das Mock-Verzeichnis muss ebenfalls bereits existieren.

Der RabbitMQ-Connection-String darf Benutzername und Passwort enthalten,
wenn der Broker nur im abgeschotteten privaten Docker-Netzwerk erreichbar
ist. Zugangsdaten bleiben dennoch geheim und gehören nicht in Git oder Logs.

`getRepository($url, $branch, $directory)` erzeugt nur einen Handle;
`directory` ist relativ zum Shared Directory. Ohne dritten Parameter nutzt
der Manager das `storageTemplate` (Standard `{repo}/{branch}`).
`getDirectory()` gibt den deterministischen absoluten Pfad zurück –
auch vor dem Checkout und ohne Git-/Netzwerkzugriff. Erst `pull()` legt
den Checkout an. Jeder RPC enthält URL, Branch und Verzeichnis.
`sync()` führt Pull und Push aus.
`ping(5.0)` prüft die Verbindung; im Mock-Modus antwortet es sofort
mit `true`.

Die Repository-API bietet außerdem `setCommitUser($name, $email)`,
`commit()`, `push()`, `hasUnpushedChanges()`, `getHistory()` und
`getBranches()`. `getFile($path, $revision = 'HEAD')` liest die committeten
Dateibytes ohne Änderung des Working Trees, z. B. `getFile('index.html', 'v1.0')`.
Auch vollständige lokale Commit-Hashes sind möglich; Mock-Repositories
unterstützen keinen versionsbezogenen Dateiabruf. `getChangedFiles()` liefert
eine `list<ChangeSet>` mit `filename` (relativer Dateipfad) und `change`
(`created`, `changed`, `deleted`) gegenüber dem letzten lokal bekannten
Remote-Stand, einschließlich lokaler Commits
und nicht ignorierter neuer Dateien. Mit `getChangedFiles('v1.0')` lässt
sich stattdessen gegen einen Tag vergleichen, ebenso gegen `HEAD` oder einen
vollständigen lokalen Commit-Hash. `getChangedFiles('v1.0', 'v2.0')`
vergleicht zwei historische Stände ohne Working Tree. In Mocks ist der Vergleich nicht
verfügbar. `setCommitUser()` legt die Identität lokal am Handle fest;
erst `commit()` sendet sie als `authorName` und `authorEmail` zum Worker.
Das vollständige Beispiel steht in
[examples/mixed-repositories.php](examples/mixed-repositories.php).
