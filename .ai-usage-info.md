# MICX Sec VCS – AI Usage

Der Worker führt Git-Operationen für das
[MICX Sec VCS SDK](https://github.com/micx-io/micx-sec-vcs-sdk) über
RabbitMQ aus. Die Anwendung benötigt keinen SSH-Key.

## Verwendung

```php
$manager = new \Micx\Vcs\MixVcsManager(
    sharedDirectory: '/vcs-share',
    connector: 'rabbitmq://micx:micx@rabbitmq:5672/micx.vcs.v1',
    storageTemplate: '{repo}/{branch}',
);
$repo = $manager->getRepository(
    'git@github.com:example/site.git',
    'main',
    'sites/site-main',
);
$directory = $repo->getDirectory(); // Immer sofort bekannt, ohne RPC.
$repo->pull(); // Legt Checkout bei Bedarf an.
$repo->commit('Update content');
$repo->sync(); // Pull + Push.
```

`getRepository()` überträgt nichts. Der dritte Parameter bestimmt den
relativen Checkout-Pfad unter dem Shared Directory; fehlt er, gilt das
Manager-Template `{repo}/{branch}`. Jeder Repository-RPC enthält
Repository-URL, Branch und relativen Pfad. Unterstützt werden ausschließlich
`ping`, `pull`, `push`, `commit`, `status`, `log` und `branches`.

Das Worker-Volume `/data` muss dem SDK unter dem angegebenen Shared
Directory bereitstehen. Git-Metadaten liegen im Checkout unter `.git`;
es gibt keine separate Workspace-Registry und keinen State-Mount.
Ein fehlgeschlagener Git-RPC liefert eine Fehlerantwort und wird bei
bestätigter Antwort nicht erneut in die Queue gestellt. Bei Broker-Abbruch
vor der Bestätigung ist eine erneute Zustellung möglich.
