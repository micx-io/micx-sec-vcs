# MICX Sec VCS
PHP-CLI-Service auf `phore/vcs`, erreichbar ausschließlich über RabbitMQ-RPC. Private SSH-Dateien unter `/run/micx`, Git-Metadaten und Request-Journal unter `/state`, Arbeitsdateien unter `/data`. `/state` niemals an Anwendungen mounten.

Start und Grenzen: [README](README.md). Protokoll und SDK-Beispiele: [Entwurf](docs/2026-09-12-secure-vcs-rpc.md). Keine globalen Funktionen.

Fehlercodes, Workspace-Sperren und Broker-Neustartverhalten: [README](README.md#fehler-parallelität-und-broker-ausfall). Ein Supervisor hält den Container bei Brokerfehlern aktiv und startet genau einen Worker mit Backoff 1–30 Sekunden neu; gemeinsame persistente Volumes erforderlich.

`create` erzeugt ein leeres lokales Repository mit Remote-URL; `checkout` holt bestehende Remote-Inhalte. Vor dem ersten Commit ist `revision` leer. Schreiboperationen brauchen nur den Workspace und fachliche Parameter; Zustandsvorbedingungen sind optional. Pull/Merge bevorzugen bei Konflikten die eigene Seite. SDK-Timeouts werden als `OperationTimeoutException` gemeldet; Remote-Abbruch ist dadurch nicht bestätigt.
